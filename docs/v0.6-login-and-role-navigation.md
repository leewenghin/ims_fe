# Frontend v0.6: Login and Role-Based Navigation

## Goal
Users log in, the token is attached to every request, logged-out users are redirected to `/login`, and the UI only shows what each role is allowed to use. Non-admin users are locked to their own branch.

## Prerequisites
Backend v0.5 and frontend v0.5 are done.

## Steps

### 1. Types
```ts
export type Role = "ADMIN" | "MANAGER" | "STAFF";
export interface Me { id: number; username: string; fullName: string; role: Role; branchId: number | null; branchCode: string | null }
export interface LoginResponse { token: string; expiresAt: string; user: Me }
```

### 2. `lib/auth.ts`
`getToken()`, `setToken(token, expiresAt)`, `clearToken()`. These use `localStorage`, and `getToken` returns null when the token has expired. Guard every access with `typeof window !== "undefined"`, because this code also runs on the server during rendering.

Security note: `localStorage` can be read by any script running on the page (an XSS risk). That's acceptable for this practice project. In production you'd store the token in an httpOnly cookie set by the server.

### 3. `apiClient` changes
- If `getToken()` returns a token, add the header `Authorization: Bearer <token>`.
- On a `401` from any request except `/auth/login`: call `clearToken()`, then `window.location.href = "/login?next=" + encodeURIComponent(location.pathname)`.

### 4. `authService`
`login(body): Promise<LoginResponse>` and `me(): Promise<Me>`.

### 5. `AuthProvider` (`"use client"`, React context)
- It provides: `user: Me | null`, `status: "loading" | "authenticated" | "anonymous"`, `login(username, password)`, `logout()`, `hasRole(...roles: Role[])`.
- On mount: if there is a token, call `me()` to load the user; otherwise set the status to anonymous.
- `logout()` clears the token, calls `queryClient.clear()` so the next user can't see cached data, and navigates to `/login`.
- Add a `useAuth()` hook that throws if it's used outside the provider.

### 6. `RequireAuth`
- Props: `children` and optional `roles?: Role[]`.
- While loading, show a spinner. When anonymous, `router.replace("/login?next=...")`. If the role isn't allowed, show a "You don't have access to this page" message.
- In `layout.tsx`: render the Sidebar and `RequireAuth` around `{children}` on every route **except** `/login`. One clean way to do this is a route group: move the authenticated pages into `src/app/(app)/` with its own `layout.tsx`, and keep `src/app/login/` outside it. Route groups don't change the URLs.

Why not do this check on the server: Next.js 16's `proxy.ts` (formerly `middleware.ts`) runs on the server, and the server can't read `localStorage`. So with this token storage, the check has to happen on the client. Storing the token in a cookie would let you move the check to `proxy.ts` (a stretch goal).

### 7. Login page
- A centered card with username, password, and a submit button. Show the error "Invalid username or password" on a 401.
- After a successful login, redirect to the `next` query parameter or `/`.
- Add a small "Demo accounts" list in dev builds (admin / manager / staff) to make testing quicker.

### 8. Role-aware UI
- Fill in `Sidebar` item `roles`: Branches = ADMIN; Users and Audit = ADMIN and MANAGER; Import = ADMIN and MANAGER; everything else is for all roles. Hide the items the user can't use.
- Show the user's name, role, branch and a Logout button at the bottom of the sidebar.
- `BranchSelect`: for non-admins, it is **fixed** to `user.branchId` and disabled.
- Products page: hide New, Edit and Deactivate for STAFF.
- New movement page: hide the Adjustment and Transfer tabs for STAFF.
- Hiding things is only for convenience. The backend still enforces every rule, so test it by calling the API directly as staff.

## Done checklist
- [ ] Visiting `/products` while logged out redirects to `/login?next=/products`, and logging in takes you back there
- [ ] `staff` sees no Branches, Users, Audit or Import links, its branch selector is fixed to KL01, and there are no product edit buttons
- [ ] `manager` sees Users, Audit and Import, but not Branches
- [ ] `admin` sees everything and can switch branches
- [ ] Logout clears cached data: log in as `pgstaff` and you see no KL01 data
- [ ] Deleting the token in DevTools and clicking anything sends you to the login page

## Stretch
- Move the token to an httpOnly cookie (set by a Next route handler that calls the backend), and guard routes in `proxy.ts`.
- Warn the user 5 minutes before the token expires.
