# Frontend v1.0: Dashboard and Polish

## Goal
A useful landing dashboard, consistent loading, error and empty states everywhere, and a clean production build.

## Prerequisites
Backend v1.0 and frontend v0.9 are done.

## Files

| Action | Path |
|---|---|
| Change | `src/app/page.tsx` (or `src/app/(app)/page.tsx`): the dashboard |
| Create | `src/components/StatCard.tsx`, `src/components/Toast.tsx` (or add `sonner`) |
| Create | `src/app/error.tsx`, `src/app/not-found.tsx`, `src/app/loading.tsx` |
| Review | every page |

## Steps

### 1. Dashboard
The data comes from endpoints that already exist. Scope it to the user's branch, or to a `BranchSelect` for admins.
- **Stat cards**: number of products in stock, number of low-stock items, and movements today (`movementService.search({ from: startOfToday, page: 0 })` and read `totalElements`).
- **Low stock list**: `inventoryService.list(branchId, true)`, showing the top 10 sorted by `quantity - reorderLevel`. Each item has a "Receive" link.
- **Recent movements**: the last 10 ledger rows, each linking to the full ledger.
- Staff see quick actions: "Scan", "Receive", "Issue".

If the dashboard needs too many requests, adding a single `GET /api/inventory/summary` endpoint to the backend is a reasonable change. Write down why you chose one approach or the other.

### 2. App-wide states
- `loading.tsx`: a skeleton shown while a route segment loads.
- `error.tsx` (`"use client"`, receives `error` and `reset`): a friendly message and a "Try again" button.
- `not-found.tsx`: a 404 page with a link home.
- **Toasts**: one place for success messages ("Received 10 x A4 Paper, balance 35"). Replace any leftover `alert()` calls.
- **Confirm dialogs**: replace `confirm()` with the `Modal` component, for consistency.

### 3. Consistency pass
- [ ] Every table has loading, empty and error states (`DataTable` handles them, so make sure every page passes them in)
- [ ] Every form disables its submit button while submitting, and shows field errors from the backend
- [ ] Dates use `formatDateTime`, and quantities show the unit
- [ ] Number inputs use `inputMode="numeric"` and `min` attributes
- [ ] Every `switch` on a union type has an exhaustive `never` default
- [ ] No `any` types (`pnpm lint` with the TypeScript rules clean)

### 4. Accessibility
- [ ] Every input has a label (`FormInput` handles this)
- [ ] The modal traps focus and closes with Escape
- [ ] Badges don't rely on colour alone (they include text)
- [ ] You can navigate the whole app with the keyboard (Tab, Enter, Esc)

### 5. Production build
- [ ] `pnpm lint` is clean
- [ ] `pnpm build` succeeds with no type errors
- [ ] `pnpm start` with the backend running: do a full walkthrough as each role

## Final walkthrough (end-to-end)
1. `admin` creates a branch `JB01` and a manager for it.
2. That manager logs in, creates a staff user, and imports opening stock from an Excel file.
3. The staff user receives with a barcode scan and issues manually; the stock goes low.
4. The dashboard shows the low-stock item.
5. The manager transfers stock in from another branch... and gets a 403, because transfers can only be made **from** your own branch. Switch to that branch's manager (or admin) and do the transfer from there.
6. `admin` reviews the audit log for the whole story.
