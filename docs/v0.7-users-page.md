# Frontend v0.7: Users Page

## Goal
Admins and managers manage users with forms that only offer the choices the backend allows. Every user can change their own password.

## Prerequisites
Backend v0.6 and frontend v0.6 are done.

## Files

| Action | Path |
|---|---|
| Change | `src/types/user.ts` (`User`, `UserCreateRequest`, `UserUpdateRequest`) |
| Create | `src/services/userService.ts` |
| Create | `src/components/UserForm.tsx`, `src/components/PasswordDialog.tsx` |
| Change | `src/app/users/page.tsx` (wrapped in `RequireAuth roles={["ADMIN","MANAGER"]}`) |
| Change | `src/components/Sidebar.tsx` (add a "Change password" action) |

## Steps

### 1. Service
`list({ branchId?, role? })`, `get`, `create`, `update`, `remove`, `resetPassword(id, newPassword)`, `changeOwnPassword(current, next)`.

### 2. Users page
- Filters: `BranchSelect allowAll` (admin only) and a role select.
- Columns: Username, Full name, Role (badge), Branch, Status, and actions (Edit, Reset password, Deactivate).
- Hide the actions on your own row (you can't deactivate yourself or change your own role).

### 3. `UserForm` role and branch rules (mirrors the backend)
| Logged-in role | Role options | Branch field |
|---|---|---|
| ADMIN | ADMIN, MANAGER, STAFF | required unless the chosen role is ADMIN, in which case it's hidden and sent as `null` |
| MANAGER | STAFF only | fixed to the manager's branch |

- In create mode, show username and password (min 8 characters, plus a confirm field). In edit mode the username is read-only and there's no password field.
- Show backend field errors under the matching inputs, and 409 (username taken) and 403 messages at the top of the form.

### 4. `PasswordDialog`
- Mode `"reset"` (admin or manager, for another user) asks for a new password and a confirmation.
- Mode `"own"` (from the sidebar) asks for the current password, a new password and a confirmation. A 400 means the current password was wrong.
- After you change your own password successfully, keep the session and show a success message.

## Done checklist
- [ ] `manager` can only create STAFF in KL01, and the role and branch controls reflect that
- [ ] `admin` creating an ADMIN hides the branch field, and the request is accepted
- [ ] A duplicate username shows the 409 message
- [ ] After a reset, the user can log in with the new password
- [ ] A deactivated user is marked inactive and can no longer log in
- [ ] Changing your own password with the wrong current password shows an error
