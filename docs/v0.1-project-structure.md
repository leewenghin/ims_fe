# Frontend v0.1: Project Structure

## Goal
Move to a `src/` layout, create the folder skeleton, proxy `/api` to Spring Boot, and build the app shell: a sidebar plus placeholder pages for every module.

## Prerequisites
Backend v0.1 is done (`GET /api/ping` works).

## Steps

### 1. Move to `src/`
Next.js picks up `src/app/` automatically, as long as there is no `app/` folder left in the project root.
```powershell
mkdir src
git mv app src/app   # or move it in Explorer if git isn't initialised yet
```
Then create the empty folders `src/components`, `src/services`, `src/types`, `src/lib`.

### 2. Path alias
In `tsconfig.json`, change:
```json
"paths": { "@/*": ["./src/*"] }
```
Now `import { Sidebar } from "@/components/Sidebar"` works from any file.

### 3. Proxy `/api` to the backend
`.env.local`:
```
BACKEND_URL=http://localhost:8080
```
`next.config.ts`: add an `async rewrites()` that returns
`[{ source: "/api/:path*", destination: `${process.env.BACKEND_URL}/api/:path*` }]`.

Why a rewrite: the browser only ever talks to `localhost:3000`, so you need no CORS configuration on Spring, and the frontend code uses relative URLs like `/api/products`.

### 4. `src/lib/apiClient.ts`
This is the single place that calls `fetch`. Contract:
```ts
export class ApiError extends Error {
  constructor(public status: number, public problem: ProblemDetail) { /* message = problem.detail ?? problem.title */ }
}
export async function apiFetch<T>(path: string, init?: RequestInit): Promise<T>
```
Behaviour:
- Prefix the path with `/api`, and set `Content-Type: application/json` when the body is a string.
- If `!res.ok`: try `res.json()` as `ProblemDetail`, fall back to `{ title: res.statusText, status }`, and throw `ApiError`.
- Return `undefined as T` for a `204` response, otherwise `res.json()`.
- Add small helpers: `apiGet<T>(path)`, `apiPost<T>(path, body)`, `apiPut<T>(path, body)`, `apiDelete(path)`.

The auth token is added in v0.6. Leave a comment where it will go.

### 5. `src/types/common.ts`
```ts
export interface ProblemDetail { type?: string; title: string; status: number; detail?: string;
  instance?: string; errors?: Record<string, string>; [key: string]: unknown }
export interface Page<T> { content: T[]; page: number; size: number; totalElements: number; totalPages: number }
```
`Page<T>` must match the backend `PageResponse` exactly.

### 6. `Sidebar.tsx`
- It's a `"use client"` component, because it uses `usePathname()` to highlight the active link.
- It takes the nav items from a constant array: `{ href, label, roles? }[]` with Dashboard, Products, Inventory, Movements, Scan, Import, Branches, Users, Audit. `roles` stays unused until v0.6.
- Use `next/link` for the links. The active link gets a different background.

### 7. `layout.tsx`
- A two-column layout: a fixed-width `Sidebar` on the left, `<main>` on the right with padding.
- Set `metadata.title` to `"IMS"`. Remove the default template content.

### 8. Placeholder pages
Each route gets a `page.tsx` that only renders an `<h1>` with the page name. `src/app/page.tsx` (the dashboard) also calls `GET /api/ping` with `apiGet` in a `useEffect` and shows the result. That proves the proxy works.

## Done checklist
- [ ] `pnpm dev` starts, and http://localhost:3000 shows the sidebar and the dashboard
