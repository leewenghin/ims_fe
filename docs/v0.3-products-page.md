# Frontend v0.3: Products Page

## Goal
A working product catalog screen: search, paging, create, edit and deactivate. You also build the reusable pieces every later page needs: `DataTable`, `FormInput`, `Modal`, and the TanStack Query setup.

## Prerequisites
Backend v0.2 and frontend v0.1 are done.

## Steps

### 1. TanStack Query
- `queryClient.ts` exports a factory `makeQueryClient()` with defaults: `staleTime: 30_000` and `retry: 1`. Don't retry 4xx errors: `retry: (n, err) => !(err instanceof ApiError && err.status < 500) && n < 1`.
- `providers.tsx` is `"use client"`. It creates the client once with `useState(() => makeQueryClient())` and renders `<QueryClientProvider>`.
- `layout.tsx` stays a Server Component and wraps `{children}` in `<Providers>`.

Why TanStack Query: it handles caching, loading and error states, and refetching after a mutation (`invalidateQueries`). That way you don't have to write a `useEffect` and `useState` pair in every page.

### 2. Types: `src/types/product.ts`
```ts
export interface Product { id: number; sku: string; barcode: string | null; name: string; description: string | null;
  category: string | null; unit: string; reorderLevel: number; active: boolean; createdAt: string; updatedAt: string }
export type ProductRequest = Omit<Product, "id" | "active" | "createdAt" | "updatedAt">
export interface ProductQuery { q?: string; category?: string; page?: number; size?: number; sort?: string }
```

### 3. `productService.ts`
Plain async functions. They are not hooks.
```ts
list(query: ProductQuery): Promise<Page<Product>>   // builds URLSearchParams, skipping empty values
get(id: number): Promise<Product>
create(body: ProductRequest): Promise<Product>
update(id: number, body: ProductRequest): Promise<Product>
remove(id: number): Promise<void>
```
Export them as `export const productService = { list, get, ... }`.

### 4. `DataTable<T>` (a generic component)
Props:
```ts
interface Column<T> { key: string; header: string; render?: (row: T) => React.ReactNode; className?: string }
interface DataTableProps<T> { columns: Column<T>[]; rows: T[]; rowKey: (row: T) => string | number;
  loading?: boolean; error?: string | null; emptyMessage?: string;
  page?: number; totalPages?: number; onPageChange?: (page: number) => void }
```
- If there's no `render` function, show `row[key]`.
- Show a "Loading..." row, an error row, or an empty-state row as appropriate.
- Show the pager (Prev/Next and "Page x of y") only when `onPageChange` is given. Note that the backend counts pages from 0.

### 5. `FormInput`
Props: `label`, `name`, `error?: string`, plus all native input props (`React.ComponentProps<"input">`). It renders a label, the input with a red border when there's an error, and the error text. Tie the label to the input with `useId()` (accessibility).

### 6. `Modal`
Props: `open`, `title`, `onClose`, `children`. It closes on Escape and on a backdrop click. A simple fixed overlay is enough. (Stretch: use the native `<dialog>` element.)

### 7. `ProductForm`
- Props: `initial?: Product`, `onSubmit(body: ProductRequest)`, `submitting`, `fieldErrors?: Record<string, string>`.
- Use controlled state, or read the values from `FormData` on submit. Choose one and learn why.
- Convert empty strings to `null` for optional fields, and convert `reorderLevel` to a number.

### 8. `products/page.tsx` (`"use client"`)
- State: `q` (debounced by 300 ms), `page`, and `editing: Product | "new" | null`.
- `useQuery({ queryKey: ["products", { q, page }], queryFn: () => productService.list({ q, page, size: 20 }) })`
- `useMutation` for create, update and deactivate. In `onSuccess`, call `queryClient.invalidateQueries({ queryKey: ["products"] })` and close the modal.
- In `onError`: if `err instanceof ApiError && err.problem.errors`, pass the errors to `ProductForm` as `fieldErrors`. For a 409 (duplicate SKU), show the `detail` message above the form.
- Columns: SKU, Name, Category, Unit, Reorder level, and actions (Edit, Deactivate). Deactivate asks `confirm()` first.

Keep the query key consistent (`["products", ...]`). `invalidateQueries({ queryKey: ["products"] })` matches every key that **starts with** `"products"`.

## Done checklist
- [ ] The list shows the products, and typing in search filters them after a short pause
- [ ] Paging works and the page resets to 0 when the search changes
- [ ] Creating a product shows it in the list without a manual refresh
- [ ] Submitting an empty form shows red messages under the right fields (from the backend's `errors`)
- [ ] A duplicate SKU shows the 409 message
- [ ] Edit pre-fills the form; Deactivate removes the row
- [ ] With the backend stopped, the table shows an error state
