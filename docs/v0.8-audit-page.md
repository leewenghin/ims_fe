# Frontend v0.8: Audit Page

## Goal
A read-only, filterable audit trail. Each entry can be expanded to show what changed.

## Prerequisites
Backend v0.7 and frontend v0.7 are done.

## Files

| Action | Path |
|---|---|
| Create | `src/types/audit.ts` |
| Create | `src/services/auditService.ts` |
| Create | `src/components/JsonDiff.tsx` |
| Change | `src/app/audit/page.tsx` (`RequireAuth roles={["ADMIN","MANAGER"]}`) |
| Change | `src/components/DataTable.tsx` (optional expandable rows) |

## Steps

### 1. Types
```ts
export type AuditAction = "LOGIN_SUCCESS" | "LOGIN_FAILED" | "CREATE" | "UPDATE" | "DEACTIVATE"
  | "PASSWORD_CHANGE" | "STOCK_MOVEMENT" | "IMPORT";
export interface AuditEntry { id: number; actor: string; action: AuditAction; entityType: string; entityId: number | null;
  branchId: number | null; details: unknown; createdAt: string }
export interface AuditFilter { actor?: string; action?: AuditAction; entityType?: string; branchId?: number;
  from?: string; to?: string; page?: number }
```

### 2. Page
- Filters: actor (text), action (select), entity type (select), branch (`BranchSelect allowAll`, admin only), and a date range. Keep them in the URL search params, so a filtered view can be shared or bookmarked.
- Columns: Time, Actor, Action (colour-coded badge: green CREATE, blue UPDATE, grey DEACTIVATE, red LOGIN_FAILED; use an exhaustive switch), Entity (`PRODUCT #12`), Branch.
- Clicking a row expands it to show the details:
  - If `details` has `before` and `after`, render `JsonDiff`: a two-column table of the keys whose values changed.
  - Otherwise show it as pretty-printed JSON (`JSON.stringify(details, null, 2)` in a `<pre>`).
- Add `renderExpanded?: (row: T) => ReactNode` to `DataTable` to support this, without breaking existing callers.

### 3. Links
For `entityType` values PRODUCT, BRANCH and USER, link the entity cell to the matching list page, filtered or highlighted to that record.

## Done checklist
- [ ] Editing a product, then opening Audit, shows an UPDATE entry. Expanding it shows only the changed fields.
- [ ] A failed login attempt appears as a red LOGIN_FAILED entry
- [ ] Filters combine correctly, and a page reload keeps them
- [ ] `manager` only sees KL01 entries; `staff` can't open the page
- [ ] There are no edit or delete controls anywhere on this page
