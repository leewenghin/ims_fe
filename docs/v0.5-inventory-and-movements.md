# Frontend v0.5: Inventory and Movements

## Goal
Show stock per branch with low-stock highlighting, show the movement ledger with filters, and provide forms for receipts, issues, adjustments and transfers.

## Prerequisites
Backend v0.4 and frontend v0.4 are done.

## Steps

### 1. Types
`inventory.ts`
```ts
export interface InventoryItem { branchId: number; branchCode: string; productId: number; sku: string;
  productName: string; unit: string; quantity: number; reorderLevel: number; low: boolean }
```
`movement.ts`
```ts
export type MovementType = "RECEIPT" | "ISSUE" | "ADJUSTMENT" | "TRANSFER_OUT" | "TRANSFER_IN";
export type MovementSource = "MANUAL" | "BARCODE" | "IMPORT" | "INTEGRATION" | "SYSTEM";
export interface Movement { id: number; type: MovementType; source: MovementSource; branchId: number; branchCode: string;
  productId: number; sku: string; productName: string; quantityDelta: number; balanceAfter: number;
  reference: string | null; reason: string | null; transferId: string | null; createdBy: string; createdAt: string }
export interface ReceiptRequest { branchId: number; productId: number; quantity: number; reference?: string; source?: "MANUAL" | "BARCODE" }
export type IssueRequest = ReceiptRequest;
export interface AdjustmentRequest { branchId: number; productId: number; countedQuantity: number; reason: string }
export interface TransferRequest { fromBranchId: number; toBranchId: number; reference?: string;
  items: { productId: number; quantity: number }[] }
export interface MovementFilter { branchId?: number; productId?: number; type?: MovementType; from?: string; to?: string; page?: number }
```
Wherever you `switch` on `MovementType`, add a `default` case that assigns the value to a `never` variable (`const _exhaustive: never = type`). If a new type is ever added, the compiler then forces you to handle it.

### 2. Services
- `inventoryService.list(branchId, lowOnly)` and `inventoryService.get(branchId, productId)`
- `movementService.search(filter)`, `receive`, `issue`, `adjust`, `transfer`

### 3. `ProductSelect`
- A search box plus a dropdown of matches. It uses `productService.list({ q, size: 10 })` with a debounced `q`.
- Props: `value: Product | null`, `onChange(p: Product | null)`.
- It shows `SKU - Name` and, once a product is selected, its unit.

### 4. `format.ts`
`formatDateTime(iso)` uses `Intl.DateTimeFormat` with the user's locale, and `formatDelta(n)` returns `"+5"` or `"-3"`. Also add a `movementTypeLabel(type)` with an exhaustive switch.

### 5. Inventory page
- Controls: `BranchSelect` (defaults to the first branch) and a "Low stock only" checkbox.
- `useQuery({ queryKey: ["inventory", branchId, lowOnly], enabled: branchId != null, ... })`. The query waits until a branch is picked. This is a **dependent query**.
- Columns: SKU, Product, Unit, Quantity, Reorder level, and Status (a red "Low" badge when `low`).
- Row actions: "Receive", "Issue" and "Adjust" link to `/movements/new?type=...&branchId=..&productId=..`.

### 6. Movements ledger page
- Filters: branch, type, product, and a from/to date range. Convert the dates to ISO instants before sending them.
- A paged `DataTable` with columns Time, Branch, Type, SKU, Delta (green when +, red when -), Balance after, Reference, Source, By.
- Rows from the same transfer share a `transferId`. Show its first 8 characters, so the two halves can be matched by eye.

### 7. New movement page (`/movements/new`)
- It reads `type`, `branchId` and `productId` from `useSearchParams()`. Because of that, wrap the client form in `<Suspense>` inside `page.tsx`. Next.js needs this for `useSearchParams` in client components.
- Show tabs for Receipt, Issue, Adjustment and Transfer. Switching tabs updates the `type` in the URL.
- **ReceiptIssueForm**: branch, product, quantity (> 0), reference. Under the product, show the current stock (`inventoryService.get`) so the user sees what's available before issuing.
- **AdjustmentForm**: branch, product, current quantity (read-only), counted quantity, and reason (required). Show the computed difference live, e.g. "Difference: -3".
- **TransferForm**: from branch, to branch (excluding "from"), reference, and a **dynamic list of items** (product and quantity) with "Add item" and "Remove". Block duplicate products and empty lists on the client too.
- On success: invalidate `["inventory"]` and `["movements"]`, show a success message with the new balance, and reset the form.
- On a 409 error: show `problem.detail` (e.g. "available 8, requested 10") next to the form.

## Done checklist
- [ ] The inventory page shows the opening stock for each branch, and "Low stock only" filters it
- [ ] Receiving from an inventory row opens the form pre-filled; after submitting, the inventory page shows the new quantity
- [ ] Issuing more than is available shows the 409 message, and nothing changes
- [ ] An adjustment shows the live difference, and the ledger shows the signed delta
- [ ] A transfer with 2 items shows 4 ledger rows with a matching transfer id
- [ ] Ledger filters and paging work
