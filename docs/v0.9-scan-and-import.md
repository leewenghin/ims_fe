# Frontend v0.9: Scan and Import

## Goal
1. **Scan page**: scan a barcode with the camera or a USB scanner, see the product and its current stock, and receive or issue it in a few taps.
2. **Import page**: upload a CSV or Excel file, review the dry-run report, then commit.

## Prerequisites
Backend v0.8 and frontend v0.8 are done.

## Part A: Scan page

### `BarcodeScanner` (`"use client"`)
- Props: `onDetected(code: string)`, `paused?: boolean`.
- It has **two inputs**, because both are common in shops:
  1. **Camera**: on "Start camera", create `new BrowserMultiFormatReader()` and call `decodeFromVideoDevice(undefined, videoRef.current, (result) => ...)`. Keep the returned `controls` and call `controls.stop()` on "Stop" and in the `useEffect` cleanup, otherwise the camera stays on after you leave the page.
  2. **USB / Bluetooth scanner**: these act like a keyboard that types the code and then presses Enter. So all you need is an auto-focused text input that calls `onDetected` on Enter, and clears and refocuses afterwards.
- **Debounce**: the camera fires the same code many times per second. Ignore a code that equals the last one if it arrived within 2 seconds.
- Browsers only allow camera access on `https` or `localhost`. To test on a phone, use an HTTPS tunnel, or run `next dev --experimental-https`.

### Scan page flow
1. Fixed branch (or `BranchSelect` for admins) and a mode toggle: **Receive** or **Issue**.
2. When a code is detected, call `productService.getByBarcode(code)`.
   - 404: show "Unknown barcode 955...". Managers also get a link to create a product with that barcode pre-filled.
   - Found: show a card with the product name, SKU, unit, and the current stock (`inventoryService.get`).
3. Quantity input (default 1) plus a big Confirm button. It calls `receive` or `issue` with `source: "BARCODE"`.
4. After success, show a toast with the new balance, then go back to waiting for the next scan. Also keep a list of "Recent scans" for this session.

## Part B: Import page

### Types
```ts
export interface ImportRowResult { rowNumber: number; status: "OK" | "ERROR"; message: string | null }
export interface ImportReport { fileName: string; totalRows: number; okRows: number; errorRows: number;
  committed: boolean; rows: ImportRowResult[] }
```

### `apiClient` changes
- If `body instanceof FormData`, **don't** set `Content-Type`. The browser has to set it itself, with the multipart boundary.
- Add `apiDownload(path): Promise<Blob>` for file downloads. A plain `<a href>` link wouldn't send the `Authorization` header.

### `importService`
- `upload(file: File, branchId: number, dryRun: boolean): Promise<ImportReport>` builds a `FormData` with `file`, `branchId` and `dryRun`.
- `downloadTemplate(format: "csv" | "xlsx")` gets the blob, creates an object URL, clicks a temporary `<a download>`, then revokes the URL.

### Import page: a two-step flow
1. **Choose**: branch, file input (`accept=".csv,.xlsx"`), and "Download template" links. Show the expected columns and an example row.
2. **Validate** sends with `dryRun=true`. Show the summary ("48 OK, 2 errors") and a table of rows. Error rows are highlighted and show their message. Add a filter for "errors only".
3. **Commit** is enabled only when `errorRows === 0`. It sends the same file with `dryRun=false`. On success, show "Imported 50 movements", invalidate `["inventory"]` and `["movements"]`, and reset the page.
4. Picking a new file clears the previous report, so you can't accidentally commit a report that belongs to a different file.
